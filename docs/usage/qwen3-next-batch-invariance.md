# Qwen3-Next batch invariance (RFC #428 `batch_invariance_ci`)

The `bi` stage checks that a Qwen3-Next-80B-A3B-Instruct sequence gets the
same bits whatever else the engines are doing: other requests in the same
vLLM step, how many there are, when they arrive, how its prompt is chunked,
and how the replay engine packs it with other sequences. It runs after a
passed `l2` stage of the [full-model chain](qwen3-next-chain.md), under the
same certified provider profile.

```bash
python tools/validation/models/qwen3_next_run.py --stage bi --previous <runs>/<...-l2-...> \
    --runs-root <runs> --checkpoint <checkpoint> --cuda-home <cuda-13.0> \
    --python <venv>/bin/python [--bi-suite quick]
python tools/validation/models/qwen3_next_chain_report.py --last <...-train-...> --bi <...-bi-...> --out chain-report.json
```

## Cells

Every cell has one *target* (16 generated tokens) and compares it bitwise -
response tokens, BF16 logits, FP32 logprobs, the embedding and every layer,
sub-node and recurrent/KV-state digest - with a reference. The cells are
generated by `rl_engine/validation/models/qwen3_next_bi_cases.py` and pinned by
`qwen3_next_bi_manifest.json`.

| Family | Cells | The target runs | Compared with |
| --- | --- | --- | --- |
| `concurrency` | 13 | with 0, 1, 3, 7, 15, 31 or 63 companions (prompts 37-1000 tokens), first or last in the FCFS order | the target alone, same chunk plan |
| `interference` | 10 | with companions of the same text, very short or long prompts, mixed lengths, arriving during its prefill, during its decode or at its last decode step, generating 1 or 24 tokens; or itself arriving after them | the target alone, same chunk plan |
| `chunk` | 66 | alone, prompt 63/64/65, 127/128/129, 527/528/529, 1023/1024 tokens, chunk 64 or 128, first chunk 1, 63 or 65 | the replay engine's recompute of the same tokens (the train/rollout boundary) |
| `packing` | 8 | in the replay engine, packed into one THD batch with 1, 3 or 7 neighbours (16-1015 tokens), first or last | the replay of the target alone |

`--bi-suite quick` runs five cells (one per family plus 64 concurrent
requests) for CI. Prompt 1025 is outside the pinned rollout profile
(`max_model_len` 1040 = 1024 + 16).

## How a cell runs

All requests of a cell are submitted together; the exact-prefill scheduler
admits a request to the waiting queue only at its `arrival_step`, counted in
scheduled steps, so arrivals are reproducible. Every prefilling request
shares one `long_prefill_token_threshold`: the target's next planned chunk
while the target prefills, the cell's chunk size otherwise. The scheduler
fails the cell if the target does not get exactly its planned tokens at
every step until its last input, or if any request is preempted. Only the
target is traced; companions generate greedily and are never recorded.
The rollout caps (64 sequences, 16384 tokens per step, 4 GiB of KV cache per
GPU) are part of the certified profile the `layers` stage qualifies.

## Results

`bi-matrix.json` lists every cell with its comparisons, the first divergent
layer and sub-node, and its layer family (`embedding`, `norm`, `gdn`,
`full_attention`, `moe` or `lm_head_logprob`). The chain report's
`batch_invariance` section summarises it per family; a failing cell fails
the chain report.
