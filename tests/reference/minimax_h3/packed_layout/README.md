# H3 packed-layout independent references

These independent artifacts were sealed before the CPU schema was implemented.
They provide expected metadata for `H3PackedLayout` and accompany the
[draft contract](../../../../docs/contracts/h3-packed-layout.md)
for [RFC #420](https://github.com/RL-Align/RL-Kernel/issues/420).

## Files and independence

| File | Origin and purpose |
| --- | --- |
| `hand_written_case.json` | Literal, hand-calculated four-row case from contract section 5. Contains original and permuted fields, source identities/roles, unique payloads, and source-order selected outputs. No generator or candidate computes its expected values. |
| `upstream_cases.json` | Thirteen cases generated by executing the pinned original upstream layout and timestep-preparation functions. Includes every input argument and exact expected tensor dtype, shape, and data. |
| `make_upstream_fixtures.py` | Reproducer that verifies complete source hashes before extracting and executing the original AST bodies. Imports neither a candidate schema nor the project's layout helper. |
| `test_packed_layout_references.py` | Offline artifact checks: sealed case identity, scalar scatter/select, permutation arithmetic, source ownership, role-specific time binding, the text-stream visual-tag exception, existing gold, and rejection of unknown generator input. |

The hand-written case deliberately uses a non-self-inverse permutation. Video
output includes a condition row and a target row: selecting video does not by
itself select only generation targets. The numeric coordinate example is
synthetic, not an upstream media-geometry fixture.

The upstream fixtures seal these original functions from Diffusers revision
`f53d552036a0d1bd5570782a39cd40cfabf112bc`:

- `MiniMaxH3PrepareLayoutStep.build_packed_sequence`;
- `MiniMaxH3Ref2VAPrepareLayoutStep.build_ref2va_packed_sequence`;
- `MiniMaxH3SetTimestepsStep.build_row_timesteps`;
- their four coordinate helpers and three rotary constants, also extracted as-is.

Source: [before_denoise.py at the fixed revision](https://github.com/huggingface/diffusers/blob/f53d552036a0d1bd5570782a39cd40cfabf112bc/src/diffusers/modular_pipelines/minimax_h3/before_denoise.py).
The complete file SHA256 is
`530b007c1d689c3ee1fc1690527f5253522d2da6b44dd326bec99faaf9f72fff`;
its Git blob SHA1 is `c670467a93075ae841c7b7cdd250ceb6fa85eda9`.
The checkpoint identity is the RFC's
`MiniMaxAI/MiniMax-H3@42ed227ee7df40d41602854ae760620d6eb651fe`.

Only static-method binding is removed and annotations are postponed. No method
body arithmetic is rewritten. The Ref2VA layout function reads reference
`kind`/`has_audio` attributes and latent tensor shapes; the reproducer supplies
simple attribute objects and shape-only tensors for those inputs. It does not
run the text encoder, VAEs, or the full pipeline.

## Coverage

| Cases | What they exercise |
| --- | --- |
| `fl2va_none`, `first`, `last`, `first_last` | Zero, first, last, and both frame anchors; rectangular grids and odd sequence lengths. |
| `fl2va_text_visual_tag` | A row from the text feature stream tagged as video, without creating a video output slot. |
| `fl2va_last_16_frames` | Fractional FP64 coordinates and the upstream last-anchor temporal construction at 16 latent frames. |
| `fl2va_same_timestep` | Equal time values collapse to one distinct table entry. |
| `fl2va_block_tiny` | The existing 264-row one-block layout; position/tag bytes retain the existing sealed hash. |
| `ref2va_image`, `audio`, `silent_video`, `video_audio`, `mixed` | Reference images, audio, video with/without soundtrack, and request-order mixtures; condition/target prefixes and up to four distinct timestep values. |

All geometries are low-level preparation inputs. Small dimensions and synthetic
text-tag lists are useful metadata cases; they do not demonstrate that a full
released encoder/pipeline accepts those requests. This coverage is an initial
reference set, not maintainer approval of the contract's D5 closeout matrix.
Empty-modality policy, general overlapping selectors, distributed execution,
real model numerics, and complete pipeline qualification remain outside these
reference checks. Real fixtures are in upstream's canonical order; schema
permutation tests compare against these plus the independent hand case.

## Exact tensor encoding

Integer tensors have `dtype`, `shape`, and integer `values`. FP32/FP64 tensors
have `dtype`, `shape`, and `data_le_hex`: exact IEEE-754 bytes in little-endian
order, flattened in C order. This avoids rounding decimal coordinate text or
depending on host byte order. Decode with `bytes.fromhex`, then a NumPy dtype
`<f4` or `<f8`, and reshape. The encoding is specific to reference artifacts;
it does not decide the future public schema's snapshot format (contract D4).

The canonical JSON SHA256 of the upstream `cases` array (sorted object keys,
separators `(',', ':')`, UTF-8) is sealed in the tests:
`51efe871dd712632675098c08f326e61831f144c5ecbcd4966cde93e1929b6d4`.
Generation environment is recorded separately so another environment can
reproduce the same cases without rewriting the original run's provenance.
The initial run used Windows AMD64, Python 3.14.3, PyTorch 2.13.0+cpu, and
NumPy 2.4.6. Other environments must check exact reproduction before claiming
the same runtime evidence.

## Offline checks

From the repository root, with project CPU/development dependencies installed:

```bash
python -m pytest tests/reference/minimax_h3/packed_layout -q
```

These checks have no network or source-download dependency and never skip for
missing diffusers/GPU/weights. The existing CI command over
`tests/reference/minimax_h3` discovers this subdirectory recursively.
They verify reference integrity independently of the schema. Schema acceptance
is covered by `tests/models/minimax_h3/test_h3_packed_layout.py`.

The broader existing H3 reference/dispatch command has a separately observed
local baseline failure in `test_h3_sigma_schedule.py`'s pinned sigma bit test:
the unchanged test also fails in isolation on the environment above, while its
sealed fixture records PyTorch 2.14.1. Its cause is not established here; neither
that implementation nor that fixture is changed by this reference work. This
must remain visible when reporting broader regression or PR readiness.

## Reproduce or regenerate

Obtain the exact linked upstream file as raw bytes in a directory outside the
repository. Do not normalize its newlines: the reproducer verifies both full
file hashes before executing any extracted source. Then, from the repository
root:

```bash
python tests/reference/minimax_h3/packed_layout/make_upstream_fixtures.py \
  --upstream-file /path/to/pinned/before_denoise.py \
  --out tests/reference/minimax_h3/packed_layout/upstream_cases.json --check
```

`--check` compares source identity, scope, generator identity, inputs, and all
expected data without writing a file. It deliberately does not replace the
recorded generation environment. A mismatch is a failure, not permission to
update expected results.

To generate a reviewable new artifact, omit `--check` and use a temporary
`--out` path first. Inspect differences against the sealed file before an
intentional update. Updating source pins or cases requires reviewing input and
expected-value changes, provenance, this coverage table, and the sealed case
digest together. Never regenerate expectations from the implementation under test.
