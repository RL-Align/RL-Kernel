# Recent128 vLLM 0.26 ABI validation on MI300X (2026-11-02)

This follow-up targets `dsv4-rocm` after items 12 and 13 were merged. It
reuses vLLM's existing Triton index kernel, with no RLK numerical kernel.

- GPU: one MI300X (gfx942); ROCm HIP 7.2.53211; PyTorch
  `2.11.0+gitd0c8b1f`; vLLM 0.26.0.
- Loaded `vllm.models.deepseek_v4.common.ops.cache_utils` source SHA256:
  `0d65322289248b9062580f8bcee90997fedf6378de456f1af8a2203484fbaee3`.
  This source's allocating wrapper lacks `out=`; its existing private Triton
  kernel accepts caller-owned output pointers. Unknown allocating-wrapper
  source hashes fail closed.
- Pinned mLite native helper source commit:
  `327a238239448de6771beea185dc6902a8de3eaa`; downloaded
  `attention/runtime.py` SHA256:
  `9646a0627d03a1c0a6d3131e41059f6f013bc319e202acd288c3d3c6d17d1170`.
- `TRITON_F32_DEFAULT=ieee`, `RLK_MEGATRON_DENSE_SOURCE` and
  `RLK_MEGATRON_DSV4_RUNTIME_SOURCE` supplied: all
  `tests/models/deepseek_v4` cases, **123 passed**, no skips. Ruff
  check/format passed. The recent128 ROCm suite alone: **14 passed**.
